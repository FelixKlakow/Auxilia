# Contributing to Auxilia

Contributions are very welcome — bug reports, fixes, features, documentation,
translations.

## Before you write code

For anything larger than a small fix, please open an issue first so we can
agree on the approach. It saves you from writing something I then have to
turn down.

## The licensing part (please read)

Auxilia is dual-licensed: source-available under the
[Business Source License 1.1](LICENSE), and separately under a commercial
license for production users.

That model only works if a single party holds the rights to the whole
codebase. Otherwise I could not offer the commercial license, because part of
the code would not be mine to license.

So: **before your first pull request is merged, you need to sign the
[Contributor License Agreement](CLA.md).**

The CLA does not take your copyright away. You keep it. You grant me a broad
licence to use your contribution in both the source-available and the
commercial distribution of Auxilia. You can keep using your own contribution
however you like.

Signing is a one-time thing, handled directly on your first pull request:
the CLA workflow comments with instructions, and you sign by replying with
its sign-off sentence.

If you are not comfortable with the CLA, that is completely fine — please
open an issue describing the change instead, and I will look at implementing
it myself.

## Pull request checklist

- [ ] Branch off `main`, one logical change per PR
- [ ] Tests pass locally
- [ ] Commit messages explain *why*, not just *what*
- [ ] CLA signed

## Code of conduct

Be decent to each other. Disagree about the code, not about the person.
